# 按设备下发定位与暂停配置

本轮实现以 [PROGRESS.md](PROGRESS.md) 的实际检查记录为准。配置由 H5 管理员保存，每台设备独立；设备加入多个家庭时共用同一份配置。

## 配置接口

`GET /api/v1/devices/{id}/config` 返回完整配置。`PUT` 相同路径提交以下五个必填字段，不提交 `version`：

```json
{
  "moving_interval_seconds": 120,
  "stationary_interval_seconds": 300,
  "moving_high_accuracy": false,
  "quiet_hours_start": "22:00",
  "quiet_hours_end": "08:00"
}
```

| 字段 | 规则与默认值 |
| --- | --- |
| `moving_interval_seconds` | 整数 60～3600 秒，必须为整分钟，默认 120 |
| `stationary_interval_seconds` | 同上，且不小于移动间隔，默认 300 |
| `moving_high_accuracy` | 布尔值，默认 false；启用后仅移动时请求高精度 |
| `quiet_hours_start` | 每日暂停开始，严格 `HH:mm`，默认 `22:00` |
| `quiet_hours_end` | 每日暂停结束，严格 `HH:mm`，默认 `08:00`，不能与开始相同 |
| `version`（只读） | 初始为 1，每次成功保存递增，旧响应不能覆盖新版本 |

管理接口需管理员 Cookie；写请求还需同源 Origin 和 CSRF。配置目标必须在当前管理员管理范围且未撤销，否则返回 404。缺失/null、类型错误、非法时间、非整分钟及越界返回 400，原配置不变。响应不含设备凭证。

合法每日同日暂停例如 `12:30`～`13:45`；跨午夜例如默认 `22:00`～`08:00`。开始时刻暂停、结束时刻可恢复，按安卓设备当前本地时区执行。暂不提供多个时段、星期设置、全天暂停或关闭时段；随时停止可使用 App 的停止共享功能。

## 下发与生效

- 位置上报成功响应返回 `accepted` 和完整 `config`。合法重复点的 `accepted:false` 也返回配置，重复点仍不更新位置与新鲜度。
- Android 0.6.0 解析完整合法配置后应用，绑定当前配对身份保存，重启读取；解除配对清除旧配置。旧服务器不返回配置或配置无效时保留本地有效配置。
- 本地保存失败或异常时保持本轮新配置生效，并提示尚未保存；后续成功上报会重试写入（包括相同版本响应）。持久化完成前重启仍可能恢复旧配置。
- 新间隔会重新安排下一次采样；移动/静止状态独立于间隔，两个间隔相同也能按状态控制高精度。普通配置变更不强行中断正在完成的单次定位。
- 收到的新暂停时间若覆盖当前时刻，立即停止本地采集、取消上传/重试、丢弃待传点，保留共享意愿及服务器最后位置。服务器已经收到的请求不能撤回。
- 暂停结束仅恢复新采集，跨过暂停时段不会补传积压点。主动停止、撤回权限或解除配对后，修改配置不会自动开启共享。
- H5 保存成功仅确认服务器已保存。已停止、离线或暂停中的客户端不主动拉取配置；暂停客户端先按本地旧配置恢复，下一次成功上报后才获取新值。
- Android 只有粗定位权限时沿用高德 SDK 的兼容定位模式，不能保证系统实际使用高精度。硬件权限、省电限频和厂商限制仍影响实际精度、间隔及暂停准点性。

地图和列表的新鲜度按每台设备 `max(420 秒, 静止间隔 + 120 秒)` 判断；同时检查原始采集时间与最后有效上报时间。默认仍为 7 分钟，最后位置不因超时自动删除。
