# 已开启共享的持续恢复

> 2026-10-19 后续省电修订：白天定位模式、唤醒锁与重试策略，以及手机本地时间 22:00–08:00 暂停/恢复，以[省电与夜间暂停设计](2026-10-19-power-saving-design.md)为准；原有共享恢复也必须遵守夜间暂停。

日期：2026-10-19。用户确认一次开启也包括手机重启后恢复；主动停止后必须保持关闭。此设计覆盖旧设计中的“不加入开机广播”和“重新打开后手动开启”。

## 已有证据

0.5.2 已持久化 `sharing_requested`，但 Activity 不读取它恢复服务，只依赖 START_STICKY。进程重建时界面使用默认关闭消息。Manifest 未声明开机权限或接收器。没有连接的 ADB 设备，不能确定 vivo 锁屏中断或 i 管家列表缺失的系统侧原因。

## 实施选择

仅修改按钮文案不能恢复上传；只依赖 START_STICKY 仍有当前缺口。采用持久意愿控制的恢复入口，供 Activity 返回前台、BOOT_COMPLETED 和 MY_PACKAGE_REPLACED 使用。不增加定时强拉进程或厂商私有广播。

- 恢复命令与首次开启区分；服务执行恢复命令时再次检查意愿，防止已排队的恢复在用户停止后误开启。
- 页面恢复时发起一次恢复请求，不按每秒刷新反复启动。意愿存在但服务不活跃时显示等待恢复，而不是共享关闭；允许停止或手动重试。
- vivo X9/API 25 在已授权定位时可尝试开机恢复。API 29+ 后台入口额外检查后台定位权限，未授予时保留意愿，打开 App 后恢复；提供系统权限入口和明确说明。隐私说明同步。
- 只恢复以前开启的共享，配对不自动开启。停止、撤回隐私、解除配对、权限撤回和明确鉴权失效继续禁止恢复。系统暂时拒绝服务启动时保留意愿，等待下次合法入口重试。
- 声明系统开机权限及非导出接收器；不保证安装后一定出现在 vivo 自启动列表，设置引导说明列表缺失时的处理及真机验证边界。

## 验证及交付

API 25/33 测试 Activity 恢复、初始关闭、停止后不恢复、重复恢复不重开会话；开机与升级入口、后台权限门控、未知广播忽略及排队恢复与停止竞态。先观察旧代码失败再修复。运行 `make android-test`、`make android-release`、Release lint，验证 APK 签名和版本，交付 0.5.3 覆盖安装包。

真机仍需分别记录锁屏 30 分钟、进程回收后重开、重启后不打开 App、停止后重启，以及原始定位时间变化。强行停止后系统可能不投递广播，需手动打开 App；不能承诺绝对后台常驻。

依据：[Android 前台服务后台启动及定位权限限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)、[vivo 官方后台运行说明](https://kefu.vivo.com.cn/robot/imgmsgData/2616a9cd7cd64a5083a264d16e5767da/index_1.html)。
