# 家庭位置共享设计

初版日期：2026-10-10；第二步补充：2026-10-12。本文为整体设计，实际交付状态以 PROGRESS.md 为准；认证配对已按[第二步设计](2026-10-12-auth-pairing-design.md)落实，位置及客户端仍为后续设计。

## 目标与约束

已确认的产品需求、设备清单和工作约定统一维护在 [PROJECT_CONTEXT.md](../../PROJECT_CONTEXT.md)，实际完成状态见 [PROGRESS.md](../../PROGRESS.md)。本设计保留具体技术方案，不能据此认定后续能力已实现。

首版 iPhone 网页只查看安卓位置，不采集 iPhone 位置。共享默认关闭，重启不自行开启；App 和常驻通知均提供停止按钮。后端单进程部署，通过 `http://服务器IP:8080` 访问。

## 方案选择

1. **采用：Go net/http + database/sql + modernc.org/sqlite**。依赖较少，SQLite 驱动不依赖 CGO，可交叉构建 Linux 二进制，适合单家庭低并发。
2. Go Web 框架 + GORM + SQLite：业务开发方便，但首步引入的抽象和依赖多于收益。
3. Go + PostgreSQL：适合多实例和高并发，本项目当前无需承担独立数据库维护成本。

应用按入口、配置、存储、HTTP 接口划分。Android 和网页统一访问后端，由后端校验身份、家庭归属和共享状态。后续网页与 API 同源部署，避免无必要的跨域开放。第一步不创建空的 Android/Web 工程。

## 全程数据流与功能边界

管理员通过服务器端初始化命令创建家庭与管理员账户（第二步已实现，禁止默认密码及公开注册）。管理员登录后生成一次性配对信息（随机配对标识和数字码），Android 在本人确认用途后提交该信息，后端绑定设备并返回独立设备令牌。后端 API 已实现，网页及 Android 界面后续实现；配对只授权设备，不自动开启定位。

Android 用户授权定位、接受高德 SDK 隐私说明并点击开启共享后，启动定位前台服务、建立共享会话、上传最新位置；网页登录后只读取同家庭正在共享且未过期的设备。停止时先在手机本地停止定位、取消上传和清空待发位置，再尽力通知服务端关闭会话并删除位置。

## Android 设计（第四步实现）

- `minSdk=25`，编译/目标 SDK 和高德版本在安卓阶段根据当时官方要求锁定并实机验证，覆盖 API 25 与 API 33。
- Android 7.1 使用兼容的前台服务启动路径；较新系统由可见 Activity 在用户操作后启动定位前台服务，声明 `location` 类型、相关权限及通知渠道。Android 13 处理通知权限拒绝，并始终在 App 内显示共享状态和停止入口。
- 请求粗略/精确定位；权限不足时明确展示精度限制。基础方案从前台启动并持续运行前台服务，不默认索取后台定位权限；若实机需求需要额外权限，再针对系统版本解释并申请。
- 同意隐私说明后才调用高德隐私授权接口和初始化 SDK；拒绝时不实例化定位 SDK。停止时销毁定位客户端，取消任务。
- 国内高德坐标按 GCJ-02 传输并显式携带坐标系；网页使用对应高德地图，避免偏移。时间传 UTC，网页按本地时间展示。
- 首次开启立即定位。初始按移动模式；速度或超过精度误差的位移触发移动模式；连续多个有效点持续约 3 分钟低速且低位移后切静止模式。阈值初值为速度 1 m/s、位移大于 `max(50m, 两点精度之和)`，实机测量后调节。
- 静止模式以约 180 秒定位/上传，移动模式约 30 秒；静止时重新移动的发现可能延迟最多一个采样周期。页面显示最后更新时间与过期状态，不用动画假装实时。
- 断网只保留内存中一个最新待上传点，连同原始定位时间及采集时确定的序号；新点替换旧点，恢复网络后仅上传这个最新点，若已采集到更新位置则发送更新点。重试不修改原始定位时间、不生成新的采集序号，不排队补传历史。系统强杀、强行停止和厂商省电限制可能中断更新，重新打开 App 后由用户主动恢复。
- 为首版 HTTP 明确配置 Android 明文网络访问；服务器地址仅由用户配置。APK 使用固定发布签名，后续升级保持包名和签名一致；签名私钥放项目内忽略目录，由用户备份。

## 登录、配对与共享（第二、三步实现）

- 单家庭起步，表中保留 `family_id`，每个请求由认证主体推导家庭，不信任客户端提交的归属。
- 密码使用成熟密码哈希方案（Argon2id），账户创建由服务端 CLI 完成。登录及配对有账户/IP 限流，登录失败返回统一信息。
- 网页使用随机不透明会话令牌及 `HttpOnly; SameSite=Strict; Path=/` Cookie；有效期 24 小时，注销即撤销。HTTP 下 Cookie 不能启用 Secure，迁移 HTTPS 时必须开启。状态变更接口校验 Origin 和 CSRF token。
- 设备令牌为至少 32 字节安全随机数，数据库只存摘要；设备使用 Authorization Bearer，独立于网页会话，支持解除配对及撤销。令牌不放 URL、不写日志。
- 配对码 8 位数字，同时附带随机 `pairing_id` 跟踪该记录的错误尝试；10 分钟有效、一次使用、最多 5 次错误尝试，并有接口限流；原子消费避免并发重复绑定。配对码只存摘要；同家庭新生成会使旧配对记录失效，具体接口见第二步设计。
- 开始共享生成新的随机 `sharing_session_id`；上传必须匹配当前会话，停止时关闭该会话。服务端在事务内检查共享状态并 UPSERT，防止停止请求与在途上传竞争后位置复活。
- 活跃共享租约为最后一次成功上报后 7 分钟（容纳 3 分钟静止间隔和网络抖动）。停止成功立即删除；离线停止立即在手机端生效，服务端最迟在租约过期后隐藏。读取时强制过滤过期数据，后台每分钟清除过期行。
- 会话内序号在采集新点时单调递增，重传保留序号；同序号重试不重复更新，低序号数据不得覆盖高序号数据，旧共享会话的数据一律拒绝。不以不可靠手机时间单独决定新旧。原始定位时间与服务端接收时间分开保存，验证经纬度范围、有限数值、非负精度、0–100 的电量百分比（不可获取时为空）、请求体大小及合理时钟偏差。
- 页面展示多人位置、精度、电量和更新时间；位置新鲜度按原始定位时间判断，接收时间只描述同步状态。过期位置不能因重新上传而被显示成新定位。共享租约与位置过期分别判断：超出租约不显示位置；租约内的陈旧点显示明确过期提示，第三步落实具体判定参数。

## 后续数据模型与接口

第一步建立 `schema_migrations`；第二步 schema v2 已加入家庭、管理员、会话、配对、设备和限流表。下表位置表及设备共享状态为第三步目标，尚未实现。

| 表 | 内容与约束 |
| --- | --- |
| families / users | 家庭、账户、密码摘要、家庭归属 |
| web_sessions | 会话摘要、用户、过期时间、撤销状态 |
| pairing_codes | 码摘要、家庭、失效时间、剩余尝试、消费状态 |
| devices | 家庭、显示名称、设备令牌摘要、当前共享会话、共享状态 |
| auth_limits | 第二步已实现：摘要化限流键、窗口开始时间、计数 |
| latest_locations | `device_id` 唯一主键；经纬度、GCJ-02、精度、电量百分比、原始定位/服务端接收时间、采集序号、租约失效时间 |

业务接口前缀 `/api/v1`：登录/注销/当前用户，生成和消费配对码，设备列表/解绑，开启/停止共享，设备 PUT 最新位置，网页 GET 家庭最新位置。第二步落实认证接口契约，第三步落实共享请求/响应结构后再开发客户端。

位置覆盖写入，不插入轨迹表；应用日志不记录坐标、请求体、口令或令牌，业务响应 `Cache-Control: no-store`。SQLite 页和 WAL 可能短暂保留覆盖前的底层字节，因此“只存最新位置”指应用数据模型不留历史，并不承诺磁盘取证级擦除。后续备份方案排除位置数据，避免备份演变成轨迹库。

## 第一步的可执行设计

本节保留第一步历史设计；当前 schema 已升级为 v2，readyz 检查程序当前 SchemaVersion。第二步新增能力以对应设计及 PROGRESS.md 为准。

目录：`backend/cmd/server` 服务入口；`backend/internal/config` 环境变量；`backend/internal/storage` SQLite 初始化及迁移；`backend/internal/httpapi` 健康检查。根目录提供 Makefile、运行说明和烟雾验证脚本。

- Go 1.26.0；SQLite 驱动锁定 `modernc.org/sqlite v1.60.1`，该版本声明 Go 1.26.0，匹配当前开发环境。
- `FAMILY_HTTP_ADDR` 默认 `:8080`；`FAMILY_DB_PATH` 默认 `data/family-location.db`，相对路径按进程工作目录解释。Makefile 始终注入项目内绝对路径，SQLite 路径必须为普通持久化文件。
- 启动时创建数据目录（新建目录 0700）、数据库文件（0600），打开数据库、设置 WAL、foreign_keys、busy_timeout、执行事务化迁移，失败则非零退出，不启动假健康服务。
- 单连接池适配首版低并发，每个新连接通过 DSN 应用 PRAGMA；第一步只迁移版本表并记录版本 1，重复启动不重复执行。拒绝比程序支持版本更高的数据库。
- `GET /healthz` 返回 HTTP 200 `{"status":"ok"}`，表示进程能响应，不查询数据库。
- `GET /readyz` 在 1 秒超时内读取迁移版本 1；可用返回 HTTP 200 `{"status":"ok","database":"ok"}`，失败返回 HTTP 503 `{"status":"unavailable","database":"unavailable"}`，不泄漏数据库路径或 SQL 错误。该检查验证可查询及版本匹配，不保证剩余磁盘空间或所有未来写操作都成功。
- 两个端点不鉴权，只暴露上述固定状态；仅允许 GET/HEAD，错误方法返回 405，未知路径 404。响应禁止缓存。
- HTTP 设置读取头、读、写、空闲超时，限制最大请求头；SIGINT/SIGTERM 最多等待 10 秒结束在途请求，然后关闭数据库。日志为结构化标准输出，第一步仅记录启动/停止/故障。

## 分阶段验收

1. 本次：真实 SQLite 文件初始化、迁移幂等与重启持久化、PRAGMA 配置、健康/就绪成功及失败、取消/超时、SIGTERM、Linux 交叉构建。
2. 认证配对：错误密码、过期/重复消费配对码、撤销、跨家庭访问、CSRF、限流。
3. 最新位置：连续上传仅一行、乱序拒绝、停止竞态、离线原始定位时间与重试序号保持、租约与位置过期分别判断、过期删除、精度/电量字段、无坐标日志。
4. Android：分别在 Mi 11 Lite（Android 13）、Redmi Note 13 Pro（Android 13）、vivo X9（Android 7.1.2）验证安装、权限拒绝/撤回、锁屏、30/180 秒目标、断网、停止、强杀、重启；记录耗电与延迟。vivo 调试通过不代表 Android 13 通过。
5. iPhone 网页：Safari 管理员登录、高德多人地图与列表、精度/电量/更新时间、过期提示、停止后消失、注销、窄屏布局；地图不可用时保留文字状态。
6. 联调部署：按服务器 CPU 架构选二进制，公网 HTTP/IP 联通，进程守护和数据权限；实际部署时确认服务器地址和登录方式。

## HTTP 和平台限制

按用户要求首版使用 HTTP/IP。HTTP 下密码、令牌、坐标可能被链路观察或篡改；密码哈希与登录鉴权无法解决传输加密问题。第二步已提供登录和设备凭证接口，位置接口尚未实现。后续 HTTPS 保留为配置升级路径。

iPhone 网页首版仅查看 Android 上报数据，不依赖浏览器定位、Service Worker 或其他必须安全上下文的能力。高德 Android key 需配置实际包名与发布签名 SHA-1；网页 key 和相关安全配置在网页阶段申请，不写入服务端私钥或账户密码。
