# 多家庭与设备上报配置设计

日期：2026-10-30。状态：用户已确认包含可配置暂停时间的完整设计，本地实现与验证已完成；实际交付及待验收边界以 [PROGRESS.md](../../PROGRESS.md) 为准。

## 已确认需求与方案选择

2026-11-06 补充：本文件中的管理员登录家庭查看链接、默认家庭依赖等规则已由[管理页与家庭访问设计](2026-11-06-admin-family-access-design.md)覆盖。新需求与完整实施设计已确认，本地代码及自动验证完成，尚未部署；设备配置与 Android 上报规则继续沿用本文件。

- 支持多个家庭及其独立标识；家庭和设备为多对多关系。
- H5 链接携带家庭标识，仅显示当前家庭成员。
- H5 提供设备配置页面：移动间隔默认 120 秒、静止间隔默认 300 秒、移动高精度默认关闭。
- 增加“不采集、不上报时间段”，默认每天 22:00 至次日 08:00，按设备本地时间执行。
- 用户已确认按设备保存配置，同一设备加入多个家庭仍使用一份配置。
- 上报响应下发配置，Android 获取新配置后应用。

推荐独立保存家庭成员关系，设备保持唯一身份、凭证和最新位置。设备只上报一次，多个家庭均可查看其位置。备选方案是在每个家庭创建一份设备记录，但会产生重复配对、上传和停止状态不一致，不适合本需求。配置归属比较了全系统统一、按家庭和按设备；用户已选择按设备。

## 家庭与权限（建议）

- 一个管理员可以创建和管理多个家庭；生成唯一随机家庭标识，支持名称和复制链接。
- 链接使用 `/?family=<家庭标识>`，沿用管理员登录。家庭标识用于选择家庭，不替代访问权限；后端校验家庭授权后过滤设备与位置。
- 默认由管理员将其管理的已配对设备加入自己管理的一个或多个家庭，不开放输入任意设备 ID 添加他人设备。跨账号共享及免登录分享不在当前建议范围；如需要，在实施前调整权限设计。
- 在选定家庭中创建配对信息，新设备配对后自动加入该家庭；已有设备通过 H5 成员管理加入其他家庭，无需重新配对。
- “移出当前家庭”只删除成员关系，不影响其他家庭及上报。“撤销设备”为独立操作，使设备凭证失效并在所有家庭清除位置。
- 没有家庭成员关系的设备仍保留在管理员设备列表，可重新加入或撤销。
- 旧链接没有标识时进入原默认家庭并补齐链接；无效或无权限标识不得回退展示其他家庭位置。
- 切换家庭时清空旧位置、取消旧请求，并校验响应代次，防止迟到响应恢复上一家庭的成员。

## 数据与迁移

- 沿用 `backend/`、现有 Go/SQLite 与嵌入式 H5。
- 增加管理员与家庭授权、设备管理归属、家庭与设备成员关系、设备配置及家庭公开标识。具体 SQL 和索引在实施计划中确定。
- 事务迁移现有管理员、家庭及设备关系，保留设备 ID、凭证、共享会话、最新位置和有效配对信息。
- 每台设备仍仅保存一条最新位置，不因多个家庭复制位置或保存轨迹。
- 旧设备配置初始化为 120/300 秒、高精度关闭、暂停时间 22:00–08:00、版本 1。旧 APK 在升级前仍使用旧逻辑，不能把数据库配置视为旧客户端已执行。

## H5 配置与接口契约（建议）

- 设备管理提供配置入口，显示设备名及所属家庭；表单单位分钟，接口统一整数秒。
- 建议两个间隔均支持 1～60 分钟，静止间隔不小于移动间隔；相等时仍按运动状态决定高精度。此参数范围待用户随设计确认。
- 暂停时间提供开始/结束两个时间选择器，使用 24 小时制 `HH:mm`，精确到分钟。建议本轮支持每天一个时间段，既支持同日也支持跨午夜；开始时刻包含、结束时刻不包含。开始与结束相同拒绝保存，避免“全天暂停”与“不暂停”的歧义；本轮不扩展多时段或按星期设置。
- 服务器校验全部字段并原子更新配置版本，拒绝缺失、错误类型和越界输入；沿用 Cookie、Origin 和 CSRF 校验。
- 新增家庭创建/列表、成员添加/移除、设备配置读取/更新接口。家庭设备列表和位置查询显式携带标识，由服务端过滤。
- `PUT /api/v1/device/location` 保留 `accepted`，成功响应新增 `config`：

```json
{
  "accepted": true,
  "config": {
    "version": 1,
    "moving_interval_seconds": 120,
    "stationary_interval_seconds": 300,
    "moving_high_accuracy": false,
    "quiet_hours_start": "22:00",
    "quiet_hours_end": "08:00"
  }
}
```

- 重复上报的 `accepted:false` 也返回当前配置，不改变序号、原始采集时间和重复上报不刷新位置的语义。
- 设备配置由认证身份确定，不能通过请求指定其他设备的配置。
- H5 保存后提示“已保存，下次设备上报后获取”，不把服务端保存成功表述为客户端已生效。
- 陈旧判断适配配置，建议采用 `max(420 秒, 静止间隔 + 120 秒)`；原始采集时间与最后有效上报时间均参与判断，旧点重传仍不能变新鲜。同步位置 API 中相关字段语义。

## Android 配置应用

- 上报结果扩展配置解析；整体校验后保存并绑定设备身份。重启恢复最后有效配置，解除配对时清除，首次无配置使用默认值。
- 配置版本阻止旧响应覆盖新值；共享代次保护继续阻止停止、解除配对或新会话后的旧回调修改运行状态。
- 收到新配置后更新策略并重新安排采样与暂停/恢复边界，无需重启 App。普通间隔/精度修改允许已进行中的单次定位结束；如果新时间段使当前时刻进入暂停，则立即停止本地定位、取消上传与重试，并丢弃待传点。已发送且服务器已接收的请求不能撤回。
- 运动判断、间隔和精度分开表达，不能再以“间隔等于 300 秒”推断静止或低功耗模式。
- 移动高精度默认关闭；开启后仅移动使用高精度，静止保持低功耗。仅粗定位授权的 SDK 兼容路径单独验证并说明实际限制。
- 将现有固定夜间判断、活动窗口与边界闹钟统一改为读取设备的有效暂停配置；默认仍为 22:00–08:00。时间或时区变更后按设备当前本地时间重算；重启使用持久化时间段。保留主动停止不恢复、断网仅留最新点、退避与短时唤醒锁。
- 暂停期间保留共享意愿及服务器最后位置；结束后只恢复新采集，不补传暂停前积压点。调整暂停时间不能自动开启用户已主动停止的共享。SDK 回调及实际网络执行前继续检查暂停规则，系统精确定时与厂商限制仍需真机验证。
- 保存配置不会主动唤醒离线、停止或处于暂停时间段的设备，需等下一次成功上报获取。已暂停设备会先按本地旧时间段恢复，成功上报取得新配置后再判断是否应暂停；页面明确提示此生效延迟。旧服务器没有配置时沿用本地有效配置；无效配置不覆盖有效值，也不将已成功上传变成无限重试。

1. 数据迁移与后端：验证旧库保留、家庭授权、多家庭成员、移除与撤销差异、配置校验和响应兼容。
2. H5：创建/切换家庭、成员管理、链接复制和配置页面；验证当前家庭过滤、迟到响应隔离及保存失败。
3. Android：解析/持久化/代次保护、相同间隔下运动与精度区分、动态重排、重启及暂停规则；覆盖默认 22:00/08:00 边界、同日/跨午夜时间段、分钟精度、相同起止拒绝、时间/时区变化、收到配置立即暂停、暂停期间修改的延迟获取、跨暂停窗口丢弃积压点及主动停止不恢复。实际 Kotlin 客户端与隔离 Go 服务联调。
4. 按改动范围运行现有 Makefile 的 Go、Node、DOM 和 Android 检查，不操作正式数据库。
5. 新 Android 版本建议 0.6.0 / versionCode 9；执行 `make android-release`，验证签名、包名、版本和摘要，保留旧交付包并提供新路径。
6. 同步需求、API、使用与部署文档及真实进度。启动仍用 `make run`，服务端升级后再覆盖安装新 APK 验证。
