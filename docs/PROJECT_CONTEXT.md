# 项目上下文：家庭位置共享

更新日期：2026-10-30。

本文件记录用户已确认的目标、需求和工作约定；技术实现细节引用[设计文档](superpowers/specs/2026-10-10-family-location-design.md)，实际完成状态以 [PROGRESS.md](PROGRESS.md) 为准。后续需求调整先更新本文件，再同步受影响的设计与计划，避免多份文档形成不同口径。设计中的具体阈值、协议细节和参数属于实施方案，不等同于已实现或已经真机验证。

## 目标

开发家庭位置共享工具：用户用 iPhone 网页查看家人安卓手机的最新位置。

## 已确认方案

- 安卓：Kotlin + 高德定位 SDK；签名 APK 直接安装，不上架应用市场。
- 安卓包名确定为 `com.jk.family`；第五步工程的 applicationId、namespace 及高德 Android Key 的 Package 保持一致。2026-10-18 用户确认 Android Key 和发布签名均已有，发现项目内已有签名库，沿用原签名；构建配置与实际签名结果见 [ANDROID.md](ANDROID.md) 和进度，不在文档记录密钥/密码。
- 后端：Go + SQLite。
- 查看端：适配 iPhone Safari 的网页，使用高德地图。2026-10-15 用户确认尚未申请 Web JS API Key，先实现页面、地图未配置降级和配置说明；真实地图与 iPhone 验收单独记录，不阻塞无 Key 的页面实现。
- 后续顺序已于 2026-10-13 确认：第三步位置后端 → 第四步 iPhone 网页 → 第五步安卓 App → 第六步部署联调。网页提前到安卓开发之前；网页阶段用独立测试设备和模拟位置验证，不冒充真实手机上报。
- 已有公网服务器；首版明确使用 HTTP + 公网 IP，HTTPS 后续再做。2026-10-15 用户补充服务器已有 Go 环境，部署说明以服务器源码构建为主，实际远程部署尚未执行。
- 白天移动约 2 分钟、静止约 5 分钟定位并上传；实际更新间隔、后台表现和耗电需真机验证。（2026-10-21 由 1 分钟/3 分钟调整）
- 2026-10-19 后续省电要求：取消持续 CPU 唤醒锁，改为网络操作期间短时持有；静止使用低功耗定位、移动恢复高精度；失败重试逐步延长到最多 5 分钟，网络恢复及时重试。用户另外要求每日 22:00 至次日 08:00 不采集、不上报，按安卓手机本地时间执行；暂停保留共享意愿及远端最后位置，早晨仅恢复新采集，主动停止后不恢复。Android 12+ 精确定时授权与系统限制说明见[省电设计](superpowers/specs/2026-10-19-power-saving-design.md)，实际完成情况见进度。
- 2026-10-20：ADB 证实只在网络执行阶段持锁无法保障休眠中的采样，用户确认调整代码。改为可唤醒设备的逐次采样调度，短时锁覆盖定位与上传及其跨线程交接，采样等待期间释放；保留移动/静止目标、失败退避、夜间暂停及主动停止不恢复。此项覆盖此前“只在网络阶段持锁、每日仅两个唤醒闹钟”的实施限制；系统深度省电限频仍可能延长间隔，不保证所有机型严格 60/180 秒。细节见[省电设计](superpowers/specs/2026-10-19-power-saving-design.md)。
- 只保存每台设备最新位置，不保留历史轨迹。
- 2026-10-19：用户反馈 vivo X9（Android 7.1.2）锁屏后位置消失，要求后台持续共享并保留最后上报位置。共享开启时，超时仅标记位置陈旧，不因 7 分钟无上报删除；主动停止成功、撤销设备仍清除。后台恢复只延续用户已开启的共享，配对不自动开启；开机恢复按下述后续确认执行，省电设置与锁屏稳定性需真机验证。实施变更见[补充设计](superpowers/specs/2026-10-19-background-location-design.md)。
- 断网仅保留最新待上传位置，保留原始定位时间；重试和恢复上传不得把定位时间改为上传时间，旧数据不能覆盖新数据。
- 2026-10-19 后续确认：点击一次开启共享后，锁屏、重新打开 App 及手机重启都应延续已开启的共享；主动停止后保持关闭。此项覆盖此前“不在开机时恢复”的约束，配对仍不自动开启。后台定位授权、厂商自启动限制与恢复入口见[共享恢复设计](superpowers/specs/2026-10-19-sharing-recovery-design.md)。
- 展示多人位置、精度、电量、更新时间与位置过期提示；延迟上传不能让旧位置显示为刚刚定位。2026-10-21 采样周期评审修复：原始定位达到 7 分钟或最后有效上报达到 7 分钟时标记更新延迟，为 5 分钟静止采样留出 2 分钟余量；最后位置仍保留，技术契约见 [LOCATION_API.md](LOCATION_API.md)。
- 家人主动开启共享，可随时停止。
- 2026-10-19：默认移动上报间隔由 30 秒改为 1 分钟；新配对标识缩短为 12 位随机字母/数字。安卓复制完整配对 JSON 后，在空白表单获得焦点时自动填写地址、标识和数字码，并提供主动粘贴入口；不自动提交配对或开启共享。见[便捷配对设计](superpowers/specs/2026-10-19-pairing-convenience-design.md)。
- 管理员登录、一次性配对码、独立设备凭证和权限校验；设备配对不代表自动开启共享。

## 2026-10-30 升级需求（设计已确认）

- 系统支持多个家庭标识，家庭包含多个设备，同一设备可以加入多个家庭；H5 链接包含家庭标识，只展示当前家庭成员。
- 新增配置页面，配置移动上报间隔（默认 2 分钟）、静止上报间隔（默认 5 分钟）及移动时是否使用高精度（默认关闭）。用户已确认按设备独立配置；同一设备在多个家庭共用其设备配置。
- 位置上报接口返回相关配置，Android 收到新配置后按新配置运行。此默认高精度设置覆盖此前“移动恢复高精度”的要求。
- 新增按设备配置的“不采集、不上报时间段”，默认每天 22:00 至次日 08:00，沿用设备本地时间；随上报响应一起下发。此项将原固定夜间时间段升级为可配置时间段，保留暂停期间最后位置及主动停止后不自动恢复的规则。
- 用户已确认[多家庭与设备配置设计](superpowers/specs/2026-10-30-multi-family-device-settings-design.md)：保留登录，一个管理员管理多个家庭并复用其管理的设备；间隔为 1～60 整分钟、静止不短于移动，暂停为每天单个不同起止的分钟时段。接口与生效说明见 [DEVICE_CONFIG.md](DEVICE_CONFIG.md)，实际交付以进度为准。
